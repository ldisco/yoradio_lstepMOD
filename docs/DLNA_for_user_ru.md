# DLNA в ёRadio / lstepMOD: актуальная инструкция для пользователя

## Важно перед началом

Этот модуль сейчас в тестовом режиме. В текущей реализации можно надежно проверить:

- что WebUI видит DLNA-блок;
- что кнопки отправляют команды в прошивку;
- что worker принимает задачи в очередь;
- что переключается источник плейлиста `WEB <-> DLNA`.

Полноценный браузинг каталога DLNA-сервера (реальные папки/альбомы через SOAP/DIDL) пока частично заглушен, это нормальное состояние для данного этапа.

---

## Что нужно настроить в сети

1. Радио и устройство с браузером должны быть в одной Wi-Fi сети.
2. Для полноценного DLNA-теста (когда будет включен полный browse) нужен DLNA/UPnP-сервер в той же сети:
   - ПК (Plex/Jellyfin/UMS/встроенный медиасервер Windows),
   - NAS/роутер с DLNA,
   - приложение на телефоне именно в режиме "server", а не только "player".
3. Если проверяете только текущий тестовый функционал кнопок/очереди, отдельный DLNA-сервер не обязателен.

---

## Где находится меню DLNA в WebUI

1. Откройте `http://<IP-радио>/`.
2. Нажмите кнопку эквалайзера (иконка с ползунками).
3. Блок `DLNA` расположен внутри всплывающей карточки эквалайзера, под ползунками `balance/trebble/middle/bass`.

Если блока нет:

- откройте `http://<IP-радио>/variables.js`;
- проверьте, что там есть `var dlnaSupported=1;`.

---

## Значения по умолчанию (что куда вводить)

В блоке `DLNA` есть 2 поля:

- `objectId` - по умолчанию `0`;
- `limit` - по умолчанию `200`.

Рекомендуемые значения для базовой проверки:

- `objectId`: оставить `0`;
- `limit`: оставить `200`.

Как работает в прошивке:

- если `objectId` пустой, автоматически подставляется `0`;
- если `limit` пустой/некорректный/меньше `1`, используется `200`;
- максимальный `limit` ограничивается значением `65535`.

---

## Назначение каждой кнопки

- `Init`  
  Ставит задачу инициализации DLNA в очередь worker (`/dlna/init`).  
  В ответе обычно `{"ok":1,"queued":1}`. Если очередь занята/переполнена, может быть `0`.

- `Status`  
  Показывает состояние worker (`/dlna/status`). Ключевые поля:
  - `running`: worker запущен;
  - `busy`: выполняет задачу прямо сейчас;
  - `processed`: сколько задач уже обработано;
  - `lastJob`: код последней задачи;
  - `queue`: сколько задач ожидает;
  - `error`: текст последней ошибки (если пусто - хорошо).

- `Список`  
  Запрос `GET /dlna/list?objectId=<...>&start=0`.  
  Сейчас это тестовый ответ-заглушка (`items: []` + `note`), нужен для проверки ответа API.

- `Build`  
  Ставит задачу сборки DLNA-плейлиста (`/dlna/build?...`).  
  Смотрим поле `queued`: `1` - задача поставлена, `0` - не поставлена.

- `Append`  
  Ставит задачу добавления в DLNA-плейлист (`/dlna/append?...`).  
  Логика очереди аналогична `Build`.

- `Плейлист WEB`  
  Переключает источник плейлиста на обычный web (`/playlist/web`).

- `Плейлист DLNA`  
  Переключает источник плейлиста на DLNA (`/playlist/dlna`).

## Рекомендуемый пошаговый сценарий проверки (чтобы воспроизвести баги корректно)

1. Откройте WebUI и блок `DLNA` в окне эквалайзера.
2. Убедитесь, что в полях:
   - `objectId = 0`
   - `limit = 200`
3. Нажмите `Status` и зафиксируйте ответ.
4. Нажмите `Init`, затем снова `Status`.
5. Нажмите `Build`, затем `Status`.
6. Нажмите `Append`, затем `Status`.
7. Нажмите `Плейлист DLNA`.
8. Обновите список/плейлист в WebUI (или откройте `http://<IP-радио>/api/playlist`).
9. Вернитесь на `Плейлист WEB`, чтобы восстановить обычный режим веб-станций.

Это минимальный стабильный цикл проверки перед поиском багов.

---

## Что считается нормальным в текущем тестовом этапе

- После `Список` отображается пустой список или заметка о заглушке browse.
- Иногда `queued=0` у `Build/Append/Init`, если очередь занята.
- В `error` может появляться служебная диагностика, если задача отклонена по "безопасному окну" выполнения.

Это не обязательно критическая ошибка интерфейса; важно фиксировать последовательность нажатий и ответы `Status`.

---

## Что отправлять в баг-репорт

Чтобы быстрее воспроизвести проблему, приложите:

1. Версию прошивки (`/variables.js`, значение `yoVersion`).
2. Последовательность кликов (например: `Status -> Init -> Status -> Build -> Status`).
3. Значения `objectId` и `limit`.
4. Ответ `Status` после каждого шага (особенно поля `queue` и `error`).
5. Был ли включен `Плейлист DLNA` или `Плейлист WEB` в момент проблемы.
